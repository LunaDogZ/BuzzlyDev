`rollback.sql` is generated by `build_rollback.py` from `snapshot-rows.json`, so
every restored policy is the live text, not a transcription. The same script
fails if any DROP in the migration names a policy that is absent from the
snapshot, is a SELECT policy, or is staff-only.

Not tested on the replica: behaviour per role (the replica has schema but no
users or rows). That is the Phase 2 probe, against the cloud, with real logins.
