## 3. เรื่องความเร็ว — ตัวเลขจริงและสาเหตุ

**สาเหตุไม่ใช่จำนวนคิวรี แต่คือความลึกของลูกโซ่** หน้าเว็บเร็วเท่าที่จำนวน
"รอบวิ่งไป-กลับที่ต่อกันเป็นทอด ๆ" ยอมให้ ตอนเน็ตอุ่นแต่ละทอด ~0.4 วินาที
**แต่ตอน cold บน Supabase free tier แต่ละทอดวัดได้ 2–5 วินาที** — ลูกโซ่ลึก ~10 ทอด
จึงกลายเป็นหน้าที่ใช้เวลา 29 วินาที

แก้ไปแล้ว 3 ทอด (2026-09-10, ยังไม่ขึ้น production จนกว่าจะ push):

| แก้อะไร | ผลที่วัดได้ |
|---|---|
| `campaigns` / `campaign_ads` / `ad_insights` ที่ไม่ได้ขึ้นกับกัน → ยิงพร้อมกัน | 3 ทอด → 1 ทอด |
| `/auth/v1/user` ที่ยิงซ้ำ 3 ครั้งเรียงกัน → อ่าน session ที่เครื่องถืออยู่ | **3 คำขอ → 0 ทุกคู่ที่วัด** · เวลาจนการ์ดแรกโผล่ 11.5→5.4 วิ · 8.9→5.5 วิ · **11.0→13.5 วิ (คู่นี้สวนทาง)** |
| 4 dialog ที่ mount ค้างทุกหน้าโดยไม่มีใครเปิด → mount เฉพาะตอนเปิด | คำขอ 51 → 41 ทุกคู่ · **เวลาไม่ขยับ** |

⚠️ **ที่ยังแก้ไม่ได้ และต้องรู้ไว้:** พื้นของฝั่ง backend ขยับเอง ระหว่างวัดวันนี้
Supabase free tier ช้าลงจนคิวรีแถวเดียวใช้เวลา **1.5 วินาที** และมีรอบหนึ่งวัดได้
**41 วินาที** โดยที่โค้ดไม่ได้เปลี่ยนอะไรเลย — ไม่มีการแก้ฝั่งหน้าเว็บใดแก้เรื่องนี้ได้
**การอุ่นหน้าไว้ก่อนขึ้นเวทีคือมาตรการจริงข้อเดียวที่ได้ผล**
