## The question

The pre-registered stance (committed in `da02849`, 2026-08-22 — before any
measurement) is:

- **Desktop preset gates KPI-4.** Pass/fail is decided there and nowhere else.
- **Mobile preset is run on the same three routes with the same protocol and
  reported as informational.** No threshold is pre-registered against it.

The reason is a build fact, not a preference: the application is desktop-only by
construction. `MainLayout.tsx:33` hard-codes `pl-72` with no breakpoint and the
sidebar never becomes a drawer; mobile was ruled an explicit non-goal by the
founder on 2026-07-23. The mobile preset additionally applies 4× CPU slowdown
and a simulated 3G profile, so it would score a viewport the product
deliberately does not serve.

**The tension we are raising rather than hiding:** proposal Objective 3 says
"responsive UI". A committee member reading closely will notice. Reporting
mobile numbers as informational answers that with data instead of silence.

**Ask:** does the advisor accept desktop-gates / mobile-reported, or should
mobile be gated too?

## Why this is asked before the numbers are used

Approval obtained in advance is pre-registration; approval obtained afterwards
is explanation. If the advisor rules that mobile gates as well, the verdict is
recomputed from the same evidence — both presets are measured either way, so
the answer changes which table decides, never which measurements exist.
